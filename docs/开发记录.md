## 给接手模型的快速入口

如果你是后续接手本项目的 AI 编程助手，请按下面顺序执行：

1. 先读 `docs/赛事导向重构规划案.md`，尤其是“给后续大模型的交接说明”和“Phase R1”。
2. 再读本文档的“当前阶段”“当前待完成 Plan”“当前已知风险”。
3. 开始任何代码修改前运行 `git status --short`。
4. 当前默认下一步是 R1：设计 SQLite schema 和 demo seed 机制。
5. 不要优先重构 UI，也不要推倒重写技术栈。
6. 每次开发结束后，必须追加一条开发记录并更新 checklist。

如果你只会按步骤执行，请照下面做：

1. 不要改 `app.py`。
2. 不要改 `modules/tools.py`。
3. 不要改 `modules/mock_data.py`。
4. 只新增 `storage/__init__.py`、`storage/database.py`、`storage/seed.py`。
5. 在 `storage/database.py` 里写 SQLite 建表和连接函数。
6. 在 `storage/seed.py` 里写 demo seed。
7. 用本文档后面的验证命令确认 seed 成功。
8. 更新本文档的“今日变更记录”和“当前待完成 Plan”。

## R1.1 具体执行说明

目标：只建立 SQLite 数据库基础设施和 demo seed，不接入现有业务。

允许新增文件：

- `storage/__init__.py`
- `storage/database.py`
- `storage/seed.py`

禁止修改文件：

- `app.py`
- `modules/tools.py`
- `modules/mock_data.py`
- `modules/persistence.py`

`storage/database.py` 必须提供：

- `DB_DIR`
- `DB_FILE`
- `get_connection()`
- `init_db()`
- `reset_db()`

`storage/seed.py` 必须提供：

- `DEMO_PROFILE_ID = "demo"`
- `seed_demo_data(reset: bool = False)`

seed 数据要求：

- 日期必须相对当前日期生成，不能写死 2026-02 或 2026-03。
- 至少包含：
  - 1 个 demo profile
  - 5 条待办
  - 8 条消费
  - 5 门课程
  - 7 天健康记录
  - 1 个旅行计划、3 个行程、5 个清单物品

验证命令：

```bash
python - <<'PY'
from storage.database import init_db
from storage.seed import seed_demo_data

init_db()
seed_demo_data(reset=True)
print("seed ok")
PY
```

```bash
python - <<'PY'
from storage.database import get_connection

tables = [
    "profiles",
    "courses",
    "transactions",
    "health_logs",
    "todos",
    "travel_plans",

with get_connection() as conn:
    for table in tables:
        count = conn.execute(f"select count(*) from {table}").fetchone()[0]
        print(table, count)
PY
```

## 当前已知风险

1. mock 日期过期。
   当前默认待办、考试和旅行计划存在写死日期，按 2026-04-24 的实际时间会导致演示内容缺失或不合理。

2. 大文件耦合。
   `app.py` 和 `modules/tools.py` 体积偏大，后续新增主动关怀和真实数据层时容易扩大改动面。

3. 缺少自动化测试。
   当前只能做语法检查，无法证明日期、预算、工具异常、持久化读写等核心逻辑稳定。

4. 比赛材料需要同步更新。
   如果代码完成重构但技术方案仍描述旧的 mock 增量覆盖架构，会削弱答辩可信度。

## 决策记录

### 2026-04-24：不做推倒重写

决策：

保留 Streamlit + DeepSeek function calling 的核心技术路线，进行垂直重构。

原因：

- 当前 UI 和 Agent 调用链路已可用。
- 比赛时间有限，换技术栈会吃掉主要开发时间。
- 赛事评分更看重可演示、可解释、可落地的 Agent 能力，而不是前端技术栈复杂度。

### 2026-04-24：mock 降级为 seed

决策：

mock 不再作为事实数据源，后续仅作为 demo 数据初始化来源。

原因：

- 真实持久化状态更适合比赛演示。
- Agent 工具调用后的状态变化必须真实影响 UI 和后续上下文。
- seed 数据仍可保证现场演示稳定。

### 2026-04-24：主动关注采用主动关怀引擎

决策：

先做 App 打开、工具执行、聊天前触发的轻量扫描机制，不急于做后台常驻心跳。

原因：

- 没有推送通道时，后台心跳收益有限。
- 比赛演示更需要可解释的状态风险事件、去重策略和今日快报。
- 后续在线部署后可再接 APScheduler、云函数或 PWA Push。

### 2026-04-24：R1.1 先只新增 storage，不接业务

决策：

下一步先建立 SQLite 基础设施和 demo seed，暂不接入 `app.py`、`modules/tools.py`、`modules/mock_data.py`。

原因：

- 降低首轮重构风险。
- 先验证数据库表结构和 seed 机制。
- 避免后续模型一次性大改导致现有 demo 失效。
