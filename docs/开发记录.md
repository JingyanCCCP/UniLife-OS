4. 任何代码修改前先 `git status --short`。
5. 只动当前激活卡里列出的「允许改动的文件」，不要顺手重构其它地方。
6. 完成后按 `docs/重构规划.md` 第 0.3 节收尾清单 + 本文档模板更新两份文档。

不确定下一步时，按 `docs/重构规划.md` 第 0.5 节兜底流程处理。

## 决策记录

> 完整版连同最新决策同步到 `docs/重构规划.md` 第 7 节。这里保留原始论证。

### 2026-04-24：不做推倒重写

保留 Streamlit + DeepSeek function calling 的核心技术路线，进行垂直重构。

原因：UI 和 Agent 链路已可用；换栈会吃掉主要开发时间；赛事评分更看重可演示、可解释、可落地的 Agent 能力。

### 2026-04-24：mock 降级为 seed

mock 不再作为事实数据源，后续仅作为 demo 数据初始化来源。

原因：真实持久化状态更适合演示；Agent 工具调用后的状态变化必须真实影响 UI 和后续上下文。

### 2026-04-24：主动关怀采用引擎化设计

先做 App 打开、工具执行、聊天前触发的同步扫描机制，不急于做后台心跳。

原因：没有推送通道时后台心跳收益有限；比赛演示更需要可解释的状态风险事件、去重策略和今日快报。

### 2026-04-25：跳过 SQLite 迁移（本轮）

本轮重构不引入 SQLite。mock 降级为 seed 的目标通过「mock 动态日期 + 演示重置脚本」实现，不走数据库迁移路径。

原因：

- 3 天 AI 辅助重构窗口太紧，9 表 schema + repository 层 + 迁移 + 业务适配至少要吃掉 10+ 小时。
- 赛事评分更看重主动关怀引擎、演示链路和鲁棒性，这些比 SQLite 本身更值得投入时间。
- JSON 增量覆盖已在多轮迭代中稳定，继续沿用风险最低。
- 演示场景里「真实持久化」通过 `data/user_data.json` 原子写入 + 动态日期 + 演示重置脚本已有说服力。

后续如果决赛前有额外时间窗口再补 SQLite 作为演进亮点。

### 2026-04-25：保持 R1→R2→R3→R4→R5 顺序

虽然 R3 主动关怀引擎是演示差异化爆点，仍按原顺序推进。

原因：

- R2 工具模块化先完成能给 R3 提供更干净的 executor 挂钩点（工具执行后扫描）。
- R1 动态日期不修，R3 的 "todo_due" / "exam_near" 等规则会在过期数据上误触发，demo 不好看。
- R4 UI 依赖 R3 的事件结构来呈现「主动关怀卡片」。

### 2026-04-25：规划案改为任务卡队列格式

接手 AI 不再需要从头读整篇规划，直接认领当前激活卡即可。同一时间只允许一张卡激活，避免跨阶段并行修改。

### 2026-04-25：模型升级走 V4-Flash 而非 V4 标准版

V4-Flash 在 function calling 任务上速度比标准版快 ~2x，且本应用 90% 调用是工具决策（短上下文 + 短回复），用 Flash 不损失质量但提升响应感。如发现 Flash 工具调用准确率明显低于 V3，再切回标准版。

### 2026-04-25：多模态走"豆包视觉 + DeepSeek 文本"双模型而非统一多模态模型

理由：

- DeepSeek 在 function calling 上是当前国内一线水平，换掉决策模型风险大
- 豆包视觉在中文小票 / 课表场景的 OCR 实测好于通用多模态模型
- 双模型分工清晰：vision 负责"看",DeepSeek 负责"决策" — 评审时也好讲故事
- 单点失败风险可控：豆包挂了不影响纯文本路径

### 2026-04-25：视觉风格走"构成主义启发"而非"纯粹 1920s 构成主义"

理由：

- 学生用户每天打开，纯黑白会显得冷峻
- 应用本身有大量数据可视化（看板图表），需要色彩系统支撑
- 保留米色 off-white + 单一暖红，既有构成主义识别度，又不丢友好底色
- 评审视觉评分更看"是否一眼不一样"而非"是否考据严格"

### 2026-04-25：R7 在 R8 之前

理由：

- R7 是功能加法（必须做才能演示多模态卖点），R8 是视觉重塑（演示前任意时段都能做）
- R7 完成后再做 R8，能在新视觉系统下顺手把 vision 工具的 UI（图片预览、缩略图卡片）也照新风格画
- 倒过来做 R8 → R7 的话，R7 加图片上传 UI 时还要再回头适配视觉，重复劳动

### 2026-04-25：不做 streamlit-extras / 自定义 component 救场

R8 全部用 CSS + 现有 streamlit 原生组件实现。不引入 streamlit-extras / 自定义 React component，因为：

- 加依赖意味着加部署复杂度
- Phase 7 的教训：动 streamlit 内部布局容易触发 rerun 循环
- 构成主义视觉要的是"克制 + 几何 + 强对比"，原生组件 + CSS 完全够
